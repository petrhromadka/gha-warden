# GW005: `actions/checkout` without `persist-credentials: false`

**Severity:** low

## What it detects

A step that uses `actions/checkout` and does not set `persist-credentials:
false`. The default is `true`, which leaves the job's token available to git
for the rest of the job.

## Why it's dangerous

By default `actions/checkout` stores the `GITHUB_TOKEN` (or the token passed
in `token:`) in the local git configuration so that later `git fetch` and
`git push` commands work. Older versions of the action wrote it directly to
`.git/config`. Recent versions write it to a separate file under
`$RUNNER_TEMP` that the git configuration includes. In both cases every later
step in the job can read the token, including third-party actions and
scripts that run code from the repository. The older layout has a second
problem: an artifact upload that includes the `.git` directory also uploads the
token. Anyone who can download that artifact can then use the token until the
job ends. Most jobs never run authenticated git commands, so the stored token
is only exposure.

## Vulnerable example

```yaml
name: build
on: [push]

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - run: make build
```

## Fixed example

```yaml
name: build
on: [push]

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - run: make build
```

If a job does need to push, keep the default for that one checkout and give
the job only the permissions it needs.

## Suppressing

Put the comment on the line the finding points at:

```yaml
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1  # gha-warden: ignore[GW005]
```

Suppress it for jobs that run `git push` or other authenticated git commands
after the checkout.
