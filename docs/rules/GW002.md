# GW002: Pwn request (untrusted checkout in a privileged workflow)

**Severity:** critical

## What it detects

A workflow triggered by `pull_request_target` or `workflow_run` that uses
`actions/checkout` with a `ref:` pointing at code from the pull request:

- `github.event.pull_request.head.sha`, `.head.ref`, or other
  `github.event.pull_request.head.*` values
- `github.head_ref`
- `github.event.workflow_run.head_sha`, `.head_branch`, or other
  `github.event.workflow_run.head_*` values

## Why it's dangerous

`pull_request_target` and `workflow_run` run in the context of the base
repository. They get a `GITHUB_TOKEN` that can write and they can read the
repository's secrets, even when the pull request comes from a fork. If such a
workflow then checks out the pull request's head and runs anything from that
tree, the attacker's code runs with those privileges. "Anything" includes
`npm install` (lifecycle scripts), `make`, a test runner, or a local action
that the pull request modified. An attacker opens a pull request from a fork
that changes `package.json` to run a script, and the script sends the
repository secrets to a server they control. GitHub Security Lab calls this
pattern a "pwn request".

## Vulnerable example

```yaml
name: pr-build
on:
  pull_request_target:
    types: [opened, synchronize]

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          ref: ${{ github.event.pull_request.head.sha }}
          persist-credentials: false
      - run: npm ci && npm test
```

## Fixed example

Use the unprivileged `pull_request` trigger for anything that builds or tests
pull request code. It runs without secrets for fork pull requests.

```yaml
name: pr-build
on:
  pull_request:
    types: [opened, synchronize]

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - run: npm ci && npm test
```

If a privileged follow-up step is needed (for example commenting on the pull
request), split the work in two. The untrusted build runs under `pull_request`
and uploads its result as an artifact. A separate `workflow_run` workflow
downloads the artifact, treats it as untrusted data, and never checks out or
executes pull request code.

## Suppressing

Put the comment on the line the finding points at:

```yaml
          ref: ${{ github.event.pull_request.head.sha }}  # gha-warden: ignore[GW002]
```

Suppress only when the checked-out code is never executed or built, and only
files are read as data, for example a label-gated job that only counts lines.
