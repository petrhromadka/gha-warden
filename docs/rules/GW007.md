# GW007: Self-hosted runner in a pull request workflow

**Severity:** high

## What it detects

A job whose `runs-on:` selects a self-hosted runner (the label `self-hosted`
or a label list that contains it) in a workflow triggered by `pull_request` or
`pull_request_target`.

## Why it's dangerous

GitHub-hosted runners are fresh virtual machines that are discarded after the
job. Self-hosted runners are ordinary machines that you manage, and they can
keep state between jobs unless you configure them as ephemeral. A pull request
workflow runs whatever the author put in the pull request: build scripts, test
code, package install hooks. An attacker who opens a pull request can use it
to run code on your runner, plant a backdoor that survives the job, read
files left by earlier jobs (including credentials and caches), and move on
to the internal network the runner sits in. GitHub's documentation says
self-hosted runners can be persistently compromised by untrusted code in a
workflow. Public repositories are most exposed because anyone can open a pull
request from a fork.

## Vulnerable example

```yaml
name: ci
on:
  pull_request:

permissions:
  contents: read

jobs:
  test:
    runs-on: [self-hosted, linux]
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - run: make test
```

## Fixed example

Run pull request jobs on GitHub-hosted runners.

```yaml
name: ci
on:
  pull_request:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - run: make test
```

If a pull request job must run on your own hardware, use ephemeral runners
(one job per runner, then removed), keep them in an isolated network without
credentials, and require approval for workflows from outside contributors.

## Suppressing

Put the comment on the line the finding points at:

```yaml
    runs-on: [self-hosted, linux]  # gha-warden: ignore[GW007]
```

Suppress it for private repositories where every contributor is trusted and
the runner is ephemeral or isolated.
