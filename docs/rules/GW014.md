# GW014: Known-compromised action

**Severity:** critical

## What it detects

A `uses:` reference (in a step or in a reusable workflow call) that matches a
publicly documented supply-chain compromise of a GitHub Action. The rule compares
the reference with an offline list that ships inside the package, with no network
access. A reference matches when it is:

- a tag or branch the advisory names as affected, or a version tag below the
  first fixed release (for example `tj-actions/changed-files` below `46.0.1`), or
- a commit SHA that the advisory names as malicious.

Owner and repository names are compared case-insensitively and exactly, so
`tj-actions/changed-files-extra` is a different action and does not match.
Local actions (`./path`) and `docker://` references are skipped. The finding
carries the advisory identifier, the compromise date, the safe guidance and the
advisory URL.

The list currently covers:

| Action | Affected references | Advisory |
|--------|---------------------|----------|
| `tj-actions/changed-files` | version tags below 46.0.1, `v35.7.7-sec`, commit `0e58ed8671d6b60d0890c21b07f8835ace038e67` | [CVE-2025-30066](https://github.com/advisories/GHSA-mrrh-fwg8-r2c3) |
| `reviewdog/action-setup` | commit `f0d342d` | [GHSA-qmg3-hpqr-gqvc](https://github.com/reviewdog/reviewdog/security/advisories/GHSA-qmg3-hpqr-gqvc) |
| `aquasecurity/trivy-action` | version tags below 0.35.0 | [CVE-2026-33634](https://github.com/advisories/GHSA-69fq-xp46-6x23) |
| `aquasecurity/setup-trivy` | version tags below 0.2.6 | [CVE-2026-33634](https://github.com/advisories/GHSA-69fq-xp46-6x23) |
| `xygeni/xygeni-action` | tag `v5`, commit `4bf1d4e19ad81a3e8d4063755ae0f482dd3baf12` | [GHSA-f8q5-h5qh-33mh](https://github.com/xygeni/xygeni-action/security/advisories/GHSA-f8q5-h5qh-33mh) |

Only incidents with a published advisory are listed. The list is a denylist of
known cases, not a scan for unknown malicious code: a clean result does not
prove an action is safe.

Limits to be aware of:

- For `reviewdog/action-setup` the advisory lists `v1` as both affected and
  patched, because the tag was re-pointed to a fixed commit. The rule therefore
  matches only the malicious commit and does not flag `@v1`. The advisory also
  names other reviewdog actions that were affected only while they pulled in the
  compromised setup action; they are not listed.
- A version below the fixed release can be reported even if the tag in the
  action's repository has been restored since. The advisories treat those
  versions as affected, so pin to a fixed release by SHA.

## Why it's dangerous

In March 2025 the `tj-actions/changed-files` tags were re-pointed to a commit
that dumped the memory of the runner process, with every secret of the job, into
the public build log. In March 2026 most version tags of `aquasecurity/trivy-action`
and all tags of `aquasecurity/setup-trivy` were force-pushed to
credential-stealing code. A workflow that ran an affected version during the
exposure window must treat every secret that was available to it as leaked.
Pinning to a full commit SHA stops tag re-pointing but not a malicious commit
that you pin knowingly, which is why this rule also matches known-bad SHAs.

## Vulnerable example

```yaml
name: changes
on: pull_request

permissions:
  contents: read

jobs:
  changed:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: tj-actions/changed-files@v44
```

## Fixed example

```yaml
name: changes
on: pull_request

permissions:
  contents: read

jobs:
  changed:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: tj-actions/changed-files@0000000000000000000000000000000000000000 # v46.0.1 or later
```

The SHA above is a placeholder: look up the commit of a fixed release in the
action's repository and review it before you pin. Then rotate every secret that
was available to runs that used the affected version.

## Suppressing

Put the comment on the line the finding points at:

```yaml
      - uses: tj-actions/changed-files@v44  # gha-warden: ignore[GW014]
```

Suppress only after you have checked that the reference does not resolve to the
compromised commit, for example in a mirror or fork you control.
