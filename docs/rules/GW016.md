# GW016: Secret interpolated into `run:` script

**Severity:** low

## What it detects

A `${{ secrets.NAME }}` (or `${{ secrets['NAME'] }}`) or `${{ github.token }}`
expression inside a `run:` script. The rule reports the exact line of the
script. It does not report a secret that is set in `env:` or `with:`, and it
skips expressions that only produce true or false, such as
`${{ secrets.NAME != '' }}` or `${{ contains(secrets.NAME, 'x') }}`, because
those do not paste the secret into the script.

## Why it's dangerous

Before a step runs, the runner replaces every `${{ }}` expression in the `run:`
text and writes the result to a script file. The secret is then part of
a file on disk, and often part of a command line, which other users on the
machine can read with `ps` and which security audit events can capture. GitHub
advises against passing secrets on the command line and recommends environment
variables or standard input instead. Log redaction is not guaranteed once the
value has been transformed or split by the shell.

The substitution also happens before the shell parses the script, so a secret
that contains a quote, a `$`, a backtick or a newline changes the script. That
makes it fail in confusing ways, and it encourages the pattern that turns
untrusted input into code injection ([GW001](GW001.md)). An environment variable
is handed to the process as plain data and is not parsed as shell syntax.

## Vulnerable example

```yaml
name: notify
on: push

permissions:
  contents: read

jobs:
  notify:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl --header "Authorization: Bearer ${{ secrets.CHAT_TOKEN }}" \
            https://chat.example.invalid/post
```

## Fixed example

```yaml
name: notify
on: push

permissions:
  contents: read

jobs:
  notify:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl --header "Authorization: Bearer $CHAT_TOKEN" \
            https://chat.example.invalid/post
        env:
          CHAT_TOKEN: ${{ secrets.CHAT_TOKEN }}
```

The same applies to `github.token`: set `GH_TOKEN: ${{ github.token }}` in
`env:` and use `$GH_TOKEN`.

## Suppressing

Put the comment on the line the finding points at:

```yaml
          echo "${{ secrets.CHAT_TOKEN }}" | tool login --stdin  # gha-warden: ignore[GW016]
```
