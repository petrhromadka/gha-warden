# GW017: Spoofable actor check in a privileged workflow

**Severity:** high

## What it detects

A workflow triggered by `pull_request_target`, `workflow_run` or
`issue_comment` that has an `if:` condition, on a job or on a step, which
trusts the identity of the actor:

- `github.actor` compared with a bot name, such as
  `github.actor == 'dependabot[bot]'` or `github.actor == 'renovate[bot]'`
  (also as `startsWith(github.actor, 'dependabot')` or with the operands
  swapped). A comparison with `!=` is not reported, because it excludes an
  identity instead of granting trust to it.
- `github.triggering_actor`, with any value.

## Why it's dangerous

`github.actor` is not the author of the pull request. It is the user that
performed the last action on it, for example the latest push or the latest
comment. An attacker cannot make Dependabot open a pull request in your
repository, but they can open a pull request in their own fork, let Dependabot
open a pull request there, and then open a pull request from that Dependabot
branch to your repository. A comment on the pull request in the fork asks
Dependabot to rebase, and Dependabot force-pushes to the branch. From then on
`github.actor` on the pull request in your repository is `dependabot[bot]`,
while the content of the branch is the attacker's.

Synacktiv used this to push code to a repository whose `pull_request_target`
workflow merged pull requests when `github.actor == 'dependabot[bot]'`. The
check looks like a hardening step, so it often sits in front of a job with a
write token, an auto-merge, or an approval. `github.triggering_actor` has the
same problem: it is the user that started or re-ran the workflow run, and it is
not a property of the code that the workflow handles.

## Vulnerable example

```yaml
name: dependabot-auto-merge
on: pull_request_target

permissions:
  contents: write
  pull-requests: write

jobs:
  automerge:
    runs-on: ubuntu-latest
    if: github.actor == 'dependabot[bot]'
    steps:
      - run: gh pr merge --auto --squash "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Fixed example

Check the author of the pull request. A pull request that Dependabot did not
open in this repository cannot have this author.

```yaml
name: dependabot-auto-merge
on: pull_request_target

permissions:
  contents: write
  pull-requests: write

jobs:
  automerge:
    runs-on: ubuntu-latest
    if: github.event.pull_request.user.login == 'dependabot[bot]'
    steps:
      - run: gh pr merge --auto --squash "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

The `dependabot/fetch-metadata` action does this check for you: it stops when
the pull request author is not `dependabot[bot]`. In any case, do not check out
or run the code of the pull request in a job that has a write token or secrets
(see [GW002](GW002.md)).

## Suppressing

Put the comment on the line the finding points at:

```yaml
    if: github.actor == 'dependabot[bot]'  # gha-warden: ignore[GW017]
```

Suppress only when the gated steps do not use a write token or secrets and do
not act on the content of the pull request, for example a job that only adds a
label.
