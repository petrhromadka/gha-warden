# GW010: Hardcoded credential in `env:` or `with:`

**Severity:** high

## What it detects

An `env:` or `with:` key whose name looks like a credential (it contains
`token`, `password`, `secret` or `api_key`, in any letter case) and whose
value is a plain string literal instead of an expression such as
`${{ secrets.NAME }}`.

## Why it's dangerous

A credential written into a workflow file is stored in the git history of
every clone and fork, and stays there after you delete it. Anyone with read
access to the repository can use it, and for a public repository that means
everyone. Because bots scan public commits for credentials, an exposed token has to
be treated as already stolen. Workflow
files are also copied into forks, logs and issue reports, which spreads the
value further. Repository secrets keep the value out of the file and mask it
in logs.

## Vulnerable example

The value below is an obviously fake placeholder.

```yaml
name: publish
on:
  push:
    tags: ["v*"]

permissions:
  contents: read

jobs:
  login:
    runs-on: ubuntu-latest
    steps:
      - uses: docker/login-action@8aa5831fb8d48d8f76594c7ddde61ae58019f550 # v4.8.0
        with:
          username: example-user
          password: EXAMPLE-NOT-A-REAL-PASSWORD
```

## Fixed example

```yaml
name: publish
on:
  push:
    tags: ["v*"]

permissions:
  contents: read

jobs:
  login:
    runs-on: ubuntu-latest
    steps:
      - uses: docker/login-action@8aa5831fb8d48d8f76594c7ddde61ae58019f550 # v4.8.0
        with:
          username: example-user
          password: ${{ secrets.REGISTRY_PASSWORD }}
```

If a real credential was committed, revoke it first. Removing it from the
file does not make it safe again.

## Suppressing

Put the comment on the line the finding points at:

```yaml
          password: not-a-secret-placeholder  # gha-warden: ignore[GW010]
```

Suppress it for values that only look like credentials, such as a public
client ID or the literal name of a secret.
